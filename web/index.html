Read your memos. The server never learns which.

To read a memo, a Zcash light wallet asks its server for the whole transaction by txid, and that request names a payment you received. Blindfetch answers the same request over private information retrieval.

The leak

One request per payment.

Compact blocks carry 52 bytes of each note, enough to find a payment and too little for its memo. So the wallet asks for the rest by txid.

A stock light wallet

One GetTransaction per received transaction, in one session, from one address. zcash-devtool carries a TODO about it, and some wallets switch memos off because of it.

GetTransaction(txid) → your payment

With Blindfetch

Every fetch is four encrypted queries for rows of a public database, with dummies shuffled in. The server answers all four without learning which rows were read.

4 × PIR query → rows → same txid
Index

Same txid, a fifth of the size.

Proofs and signatures sit outside the txid (ZIP 244, ZIP 229). The indexer zeroes them, collapses the zeros and checks that every transaction still hashes to its txid.

Fetch

Four queries, every five minutes.

YPIR, from the Zellic-audited valar-ypir crate that ZODL uses for shielded voting, hides which row each query asks for. The wallet sends the same round on a timer whether or not anything arrived.

Verify

Every answer checked, dummies too.

The index carries a hash of every row. The wallet checks all four answers and recomputes each txid. A server that sends anything wrong is locked out, and keeps getting dummy traffic so it cannot tell whom it caught.

FAQ

Questions worth asking.

Does the server have to be trusted?

Not with which transactions you read. PIR keeps that from it, and every answer is checked against the index and the txid. It can refuse service, and it sees your address and when you connect, like any server.

Why not hide the request among decoy txids?

A server that sees your real txid among seven decoys learns that one of eight is yours, and repeated fetches narrow it down. Here every request covers the whole database.

Why not download every transaction?

That is about 8 MB per day of chain, so a wallet offline for a week would download about 55 MB. A Blindfetch round is about 2 to 3 MB up and 0.5 MB down.

What about memos from before Ironwood?

They are not in the database. In Blindfetch mode zcash-devtool leaves them pending and never sends their txids to lightwalletd.

Which wallets can use it?

zcash-devtool today. Any wallet built on librustzcash answers the same enhancement request, and the integration guide shows the change.

Who runs the server?

For this demo, the author, on a laptop. Anyone can run one with a lightwalletd endpoint, and wallets can compare two servers' indexes before trusting either.
